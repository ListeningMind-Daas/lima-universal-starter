# 표준 7잡 (① 계층 · 잡 플레이북)

발화를 한 잡(주축)으로 분류하고 보조 잡을 붙인다. 각 잡: 질문 → 커넥터 → 절차 → 산출 → 실측에서 배운 함정.

## 잡 선택표

| 알고 싶은 것 (이용씬) | 잡 | 주 커넥터 | 범용 예시 발화 |
|---|---|---|---|
| 얼마나 커/뜨나 · 전년 대비 · 시즌성 · 라이징 · 급등 원인 | **1 수요·트렌드** | keyword_info (+trend_finder) | "캠핑용품 검색 추이", "전기자전거 시즌성" |
| 왜 찾나 · 어떤 상황 · 무엇을 따지나 | **2 니즈·구매요인(CEP·KBF)** | cluster_finder (+intent_finder) | "노트북 살 때 뭘 따지나", "반려동물 사료 진입 상황" |
| 인지→검토→행동 경로 · 이탈 · 관문 | **3 검색여정(CDJ)** | path_finder | "유학 준비 검색 경로", "중고차 비교 여정 이탈" |
| 누가 존재감 · 검색 점유 · 비교 소환 | **4 경쟁·브랜드(SoV·SoJ)** | cluster_finder + keyword_info | "헬스장 프랜차이즈 SoV", "브랜드 A vs B 검색 점유" |
| 어떤 질문을 콘텐츠·광고로 | **5 콘텐츠·기회** | intent_finder (+serp·keyword_info) | "코딩 교육 콘텐츠 기회", "광고 키워드 후보" |
| 누가 검색하나 · 성/연령 · 세그먼트 | **6 세분화·타겟팅** | keyword_info.demography (kr) | "20대 vs 40대 관심사 차이" |
| 지금 진입/확장해도 되나 · 종합 | **7 종합·진입** | 위 조합 | "이 카테고리 지금 들어가도 되나" |

**tie-breaker** — 연관어 *목록* → 5(intent_finder). 관계·군집 *구조* → 2/4(cluster_finder). "왜" → 2. "누가" → 6.
"비교/구도" → 4. "경로/이탈" → 3. "지금 밀까/종합" → 7.

## 잡1. 수요·트렌드
- **절차**: `demand-pipeline.md`(D1~D8 · `scripts/collect_demand.py`) — 시드 레이어 설계(문제·시장·브랜드·대체재 + 재화 유형 층)
  → 시드 검증 프로브를 연관어 확장으로 재사용 → 고볼륨 시드 구조 탐색(cluster_finder/keyword_list hop 1) → 유니크 정리·제외 표시
  → 유니크 전체 keyword_info(ads_info) 월별 48개월 → 노이즈·시계열 동일 행·구글 공유 변형 제거 → 최근 24개월 차트 + 장기 방향 병기
  → YoY(최신 미완월 제외, 최근 12개월 vs 직전 12개월) → 시즌 지수(달별 평균/전체 평균, 피크 1.5 이상, 진폭 = max/min) → 채널(kr: 네이버/구글 비중).
  **라이징은 키워드 단위로 본다** — 카테고리 합계가 조용해도 키워드는 뛴다(`collect_demand.py rising`: 최근 3개 완결월 평균 vs 전년 같은 달).
  라이징 원인은 `explain`이 구별 토큰(인물·모델·정책명)으로 trend_finder를 부르고 품목 어휘가 함께 나오는 이슈만 남긴다 —
  급등 키워드를 통째로 시드로 넣지 않는다(단어 하나만 맞아도 이슈를 가져온다). 매칭이 1,000건을 넘으면 판정 보류.
- **산출**: 수요 추이·시즌 리포트, KPI(월평균·YoY·시즌 진폭·피크월).
- **함정**: 동의어군이 같은 볼륨을 공유한다 → 합산 전 dedup(실측: 624,250→472,400). 롱테일 다수는 임계 미만
  (3,716개 중 452개만 볼륨) → 규모가 아닌 언어 근거로. 시즌 품목은 연평균 인용 금지. 검색량≠매출.

## 잡2. 니즈·구매요인 (CEP·KBF)
- **절차**: 시드 검증 → cluster_finder 군집(먼저 `/keyword_list`로 반환 고유 키워드 수를 보고 limit을 정한다 · hop 2는 그 수를 확인한 뒤) →
  군집을 6층으로 분류(근거 쿼리 병기) → keyword_info로 볼륨 검증 → 카드 내 볼륨 내림차순, 약한 노드는 "해석 보류".
  CEP 허브의 근거가 모자라면 허브 검색어의 serp(연관 질문·AI 개요)로 보강하고, "왜 지금"은 trend_finder(구별 토큰)로 본다 —
  CEP Finder 엔진(S2 증거)과 같은 방식이며 발췌마다 수집 시각·원본 파일을 남긴다.
- **상황형 CEP는 품목 쿼리에 없다** — 상위 앵커("신혼 가전 리스트"·"집들이 선물")와 여정 co_path에서 찾는다.
  검색어는 상황 슬롯을 최대 2개만 담는다(3슬롯 0%) → co_path가 co_query보다 13배 많이 잡는다.
- **KBF 서열은 CEP마다 뒤집힌다** — 카테고리 전역 상수로 쓰지 않고 "이 상황에서의 서열"로.
- **산출**: 결정구조 6카드 · 컨셉/RTB 요건 · 화이트스페이스.
- **함정**: 제품 속성을 CEP로 적기 · 회피 요인을 제품 성능 진술로 쓰기 · 군집 라벨을 실측처럼 쓰기(`[파생]`).

## 잡3. 검색여정 (CDJ)
- **절차**: 검증된 시드 → path_finder(limit 150) → 진입·탐색·비교·검증·행동·행동 후 단계로 접기 → 허브·분기·
  이탈 노드 → 마찰(불안·미해결 질문) → 개입 포인트.
- **path_finder는 세션 인접만 잡는다** — 생애 이벤트→카테고리 크로스는 돈이 붙은 이벤트(전세·이사)에서만 관측됨.
  상황형 여정은 상황 앵커에서 카테고리 도달률을 측정값으로 보고한다(게이트가 아니다).
- **산출**: 단계 플로우 · 이탈 분기 · 개입 포인트. 리테일 관점이면 종착 채널 분포.
- **함정**: 희소 엣지로 퍼널 단정 · 전이를 개인 이동처럼 서술 · 핵심 4커넥터 중 최고가이므로 limit 통제.

## 잡4. 경쟁·브랜드 (SoV·SoJ)
- **절차**: 수요 파이프라인(`demand-pipeline.md`)으로 키워드 집합을 모은 뒤 `collect_demand.py share` — 헤드라인 층 집계 키워드를
  브랜드(E0 Brand)·판매 채널(E0 Channel)·무브랜드로 나누고, 점유율은 브랜드 지명 합 대비와 헤드라인 전체 대비 두 분모로 낸다.
  브랜드 별칭은 `entity-dictionary.md` 규칙(기업명 단독 제외·채널 분리 · 일반 제조사명 단독 금지). 모델명은 M3 층 프로브·구조 탐색이
  모은다 → **브랜드+모델 합산**(모델을 빠뜨리면 상위 브랜드 점유가 낮게 잡힌다). `share`가 내는 미등재 브랜드·유형 후보를 사람이 골라 E0에
  넣고 build → share를 다시 돌린다(0크레딧). 비교 여정 소환(SoJ)은 path/cluster에서. 검색 결과 노출 점유(누가 상위에 뜨나)는
  `content --serp-top`의 사이트 분포로 보되 구글 결과라는 점을 함께 적는다.
- **산출**: SoV 막대(브랜드 vs 판매·중개 채널 구분) · 매칭 별칭 공개 · 포지셔닝 갭.
- **함정**: 사전 공백은 SoV가 아니라 **분모**를 먼저 망친다(미등재 브랜드 7만+ → 브랜드 지명 43.9→53.9%).
  Generic(무브랜드) 행은 분리 표기. 비브랜드 카테고리(신선식품 등)는 브랜드 SoV 대신 채널·산지 SoV.

## 잡5. 콘텐츠·기회
- **절차**: 수요 파이프라인 키워드 집합 → `collect_demand.py content` — 목적별 묶음(문제해결·구매·비교·검증·정보·사용·탐색)과
  권장 형식 · 시드(헤드텀)를 뺀 비중 병기 → `--serp-top N`으로 상위 검색어 serp(키워드당 30): 연관 질문(PAA)·AI 개요 노출·
  자연결과 상위 사이트 → 구분(disambiguation) 콘텐츠·비교표·FAQ·랜딩 요건. CPC·경쟁도가 필요하면 상위 검색어에 ads_metrics,
  SERP 피처 월별 이력이 필요하면 상위 N개에만 `all`. 최근 이슈 소재는 `explain`의 라이징 원인 이슈를 쓴다.
- **SERP는 구글 결과다** — `content`가 조회 검색어들의 구글 비중(gg/(gg+nv))을 함께 낸다. 네이버 비중이 큰 품목(2026-09-30 파일럿: 구글 25%)에서
  구글 결과만으로 노출 지형·콘텐츠 우선순위를 단정하지 않는다. 조회 시점 스냅샷이라 시계열 비교에 쓰지 않는다.
- **산출**: 콘텐츠 백로그(쿼리군·볼륨·의도·형식) · 광고 키워드 후보(규제 도메인은 "심의·준법검토 전 초안").
- **함정**: AIO는 가설의 원천이지 소비자 발화가 아니다(노출 89%라도 실측으로 교차 확증). 카피는 한 메시지 =
  완결형 한 문장, 무출처 정밀 수치 금지.

## 잡6. 세분화·타겟팅
- **절차**: keyword_info.demography(kr) → 성·연령 분포 → 세그먼트별 쿼리군 비교(군집×인구) → 세그먼트 격차·공백.
  인구 데이터는 `all`(키워드당 10)에만 있다 — 수요 파이프라인 `keywords_master.csv`의 헤드라인 층 상위 N개(볼륨순)에만 부른다.
- **gl=us/jp**: demography 없음 → 과업(JTBD)·구매기준·여정 기반 세그먼트 정의로 대체하고 배너에 사양 명시.
- **산출**: 세그먼트 맵 · 세그먼트별 KBF/CEP 차이.
- **함정**: 민감 속성 추정 금지 · 비율을 개인으로 환원 금지 · 상위 브랜드와 하위 라인을 분리 비교(뭉치면 차이 소실).

## 잡7. 종합·진입
- **입력**: 수요 파이프라인 산출물을 그대로 쓴다 — `core/demand_metrics.json`(TAM·YoY·시즌) · `rising_explained.json`(지금 뜨는 것·원인 →
  지켜볼/위험 근거) · `brand_share.json`(경쟁) · `content.json`(콘텐츠 기회).
- **절차**: TAM(수요) → CEP(맥락) → 경쟁(SoV·갭) → 여정(관문·마찰) → 근거(RTB) 순으로 엮어 "어디·언제·어떻게"
  진입/확장할지 + 확신 경계. 카테고리 리포트 스파인(TAM·세그먼트 구성·Intent Mix)을 쓴다.
- **산출**: 진입 판단 원페이저 · 기회 백로그(지금/지켜볼/위험).
- **함정**: 옴니버스화 · 권고를 단정으로 쓰기 · 내부 데이터(매출·조달·가격)가 필요한 결정을 검색으로 답하기
  → "내부·외부 결정 필요"로 비워 둔다.
